media acceptance profile cannot run unchanged: it retains files and includes
longer fault cases. No recording was required for the independent GPU/engine
probes below.

NixOS apply, permanent settings, service enablement, privileged helper changes,
public streaming/listeners, unrelated deletion, and source publication remain
prohibited. Runtime gates and autostart targets stay disabled.

## Decisions and ownership

Three independent design candidates converged on an owned single-utterance
playback operation before external event/transport integration. They were not a
multi-model review. The alternative Agent WAV endpoint/claim lifecycle adds
listeners and state before playback or capture execution is established, so it
was not selected. Future transport and EventSub APIs are not added as stubs.

The [fixture command](../poc-speech.md) reuses `pw-play` and the existing Rust
process owner. Shared WAV validation remains in `tts.rs`, including synthesis.
Playback feeds checked raw PCM through stdin instead of creating another WAV
cache or a temporary playback file. This removes a file owner and deletion
failure path. Normal Agent speech refusals remain intact.

The binary owns its signal handler and cancellation bridge. The finite operation
owns only its player and bounded pipes. It does not own the game, existing OBS,
the shared audio server, capture, microphone, or any prior readiness-session
service activation. Player completion is separate from physical listening.
